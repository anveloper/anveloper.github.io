# PHP 레거시 마이그레이션 & 외부 커머스 연동

## 개요

입사 당시 회사의 주력 솔루션은 **파일 하나가 5천~1만 줄에 달하는 15년 된 PHP 코드베이스**였습니다. 구조를 파악하는 데만 오랜 시간이 걸려 신규 입사자가 적응하지 못하고 연쇄 퇴사하는 상황이 반복되고 있었습니다.

레거시를 그대로 두고 기능만 얹는 대신, 신규 스택 전환을 상급자에게 건의하고 **단독으로 맡은 앱스토어 확장 프로젝트에서 직접 증명하는 전략**을 세웠습니다. 그 결과가 조직 전체의 Next.js·React·Prisma 전환으로 이어졌습니다.

## 배경

- 15년 누적된 PHP 레거시 — 파일당 5천~1만 줄, 디렉토리 구조와 핵심 로직이 문서화되지 않음
- 신규 입사자가 코드를 읽지 못해 온보딩이 실패하고, 이것이 연쇄 퇴사로 이어지는 구조적 문제
- 수정 범위를 예측할 수 없어 기능 하나를 고치는 데도 회귀 위험이 큰 상태

전환을 주장하려면 근거가 필요했기에, 먼저 **스파게티 코드의 디렉토리 구조와 핵심 로직을 분석해 팀에 공유**하고 마이그레이션 로드맵을 제시했습니다.

## 담당 역할

세 개의 외부 커머스 플랫폼 연동을 **모두 단독으로** 담당했습니다.

### Shopby(NHN) 앱스토어 확장 (2023.03 ~ 2023.05)

- 구형 에디터 솔루션을 Shopby 플랫폼으로 확장
- 외부 커머스 플랫폼의 앱 규격·인증 흐름을 처음부터 파악해 적용

### Shopify 앱스토어 확장 (2023.06 ~ 2024.01)

레거시 재구현의 실증 사례가 된 프로젝트입니다.

- 구형 PHP 솔루션을 **Remix · React · TypeScript**로 전면 재구현
- Shopify App Remix + Polaris 기반 관리자 화면 — 상품 목록, 주문 목록, 설정, 가입, 가이드
- **Liquid 테마 연동**으로 쇼핑몰 스토어프론트에 에디터 진입점 주입
- Prisma로 세션·설정 데이터 관리, GDPR 필수 웹훅(고객 데이터 조회·삭제, 샵 데이터 삭제) 대응
- 자사 디자인 에디터(Jarvis) API 연동

### Cafe24 앱스토어 연동 (2023.03 ~ 유지보수 지속)

- 에디터 솔루션의 Cafe24 앱 연동 개발 및 지속적인 유지보수
- 이후 DPS·Estimator의 Cafe24 연동으로 이어지는 기반이 된 작업

## 기술 스택

| 분류         | 기술                                    |
| ------------ | --------------------------------------- |
| 신규 스택    | Remix 2, React 18, TypeScript 5, Vite 5 |
| 플랫폼 SDK   | Shopify App Remix 2, Polaris 12         |
| ORM          | Prisma 5                                |
| 레거시       | PHP, VanillaJS                          |
| 스토어프론트 | Liquid (Shopify 테마)                   |
| 연동 대상    | Shopify · Shopby(NHN) · Cafe24          |

## 성과

- **조직 전체의 스택 전환을 이끌었습니다.** 단독 프로젝트에서 Remix·React·TypeScript 재구현의 실효를 보인 것이 근거가 되어, 기술연구소 주축으로 회사 솔루션의 **Next.js·React·Prisma 전면 전환**이 결정됐습니다. 이후 DPS·DPS Store가 이 스택 위에서 만들어졌습니다.
- **데이터 정합을 유지했습니다.** 주문·재고·정산 데이터가 자사 시스템과 외부 커머스 플랫폼 사이에서 어긋나지 않도록 동기화 흐름을 설계했습니다.
- 레거시 분석 결과와 마이그레이션 로드맵을 문서로 남겨, 팀이 전환 범위를 판단할 수 있는 근거를 만들었습니다.

## 회고

기술부채를 "언젠가 갚아야 할 것"으로 미루지 않고, **말 대신 증명으로 설득한 경험**이었습니다. 레거시 전환은 조직의 의사결정이 필요한 일이라 개인이 주장만으로 바꾸기 어렵습니다. 단독으로 맡은 프로젝트를 새 스택으로 완성해 동작하는 결과물을 보여준 것이, 전환 논의를 실제 결정으로 옮기는 가장 효과적인 방법이었습니다.

외부 커머스 플랫폼 세 곳(Shopify·Shopby·Cafe24)을 연달아 붙이면서, 플랫폼마다 다른 인증·앱 수명주기·데이터 규격을 다루는 감각을 얻었습니다. 이 경험은 이후 DPS의 스마트스토어·Cafe24 연동과 Estimator의 Cafe24 앱 설계로 그대로 이어졌습니다.
